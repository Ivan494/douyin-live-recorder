# v1.2.3 发布验证

## 目标与边界

合并录制及媒体稳定性修复，修复完整发布流程，验证最终发布包不包含个人资料与登录数据，再发布补丁版本。保留个人安装的配置和录制文件。发布检查覆盖本次源码与构建产物，不改写仓库历史。

## 修复

- 根目录增加独立启动器，解压后可直接启动。启动器将参数正确传给内部程序，支持中文和空格路径。
- 构建检查所有外部命令退出码，检查 FFmpeg 和 FFprobe 都存在。只清理经过路径验证的当前版本输出，不删除整个 dist。
- 独立构建环境使用 requirements-release.txt 锁定依赖；补充签名模块、Streamget 资源和组件元数据收集。
- 新增离线 EXE 自检：不读取个人账户、不启动监控、不访问网络，验证持久化路径、Tk、签名模块、资源文件、FFmpeg/FFprobe。
- 白名单控制压缩包内容，拒绝额外文件、重复路径、越界路径和符号链接；配置必须与批准的空白默认模板一致。
- 源码检查拒绝已跟踪的个人会话、设备文件、日志、录制文件及明显的凭据格式。
- 检查 EXE 内嵌文件清单，拒绝个人配置与诊断测试模块；压缩包附带文件哈希清单和外部 SHA256SUMS.txt。
- PR 先运行完整构建与解压自检。发布任务只接收验证后的产物，核对哈希，再将上传完整的草稿 Release 公开。
- 发布说明与升级说明使用简体中文，提醒保留旧配置，避免空白模板覆盖个人配置。

## 本地证据

- 干净虚拟环境运行 **173 项测试和 8 项子测试，通过**。
- 本地完整构建通过，根目录启动器在中文/空格路径中运行 EXE 自检成功。
- 自检通过项目：persistent-paths、signing-and-resources、tk-interface、ffmpeg、ffprobe。
- 发布压缩包只包含启动器、内部 EXE、空资料/默认设置、两个媒体工具、使用说明、许可证说明及完整性清单。
- 演示截图已人工查看，资料名称与账户区域保持遮挡；个人安装目录没有作为构建输入。

第三方库内部实现不等于本项目用户的个人状态。本次检查不构成对整个依赖生态的安全证明；未进行新登录、全部外部网站功能或所有 Windows 环境的穷尽测试。
